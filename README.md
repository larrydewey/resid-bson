# resid-bson

[BSON](https://bsonspec.org/) as a format for
[resid-serial](../resid-serial), the serialization framework. Any type with
`Encode`/`Decode` instances — written by hand or generated by `resid-derive`
— goes to BSON and back with these.

```resid
import "src/bson.resid";

Int main() {
    Result(List(Int), SerialError) bytes = to_bson(Point {.x = 1, .y = 2}) else { return 1; };
    println(bs_hex(bytes));                      // 13000000 107800 01000000 107900 02000000 00
    Result(Point, SerialError) back = from_bson(bytes) else { return 1; };
    println(f"{back}");
    return 0;
}
```

## Entry points

| Call | What it does |
|---|---|
| `to_bson(T x) -> Result(List(Int), SerialError)` | the bytes |
| `from_bson(List(Int) bs) -> Result(T, SerialError)` | one value, then `read_end` rejects trailing bytes |
| `to_bson_hex(T x) -> Result(Str, SerialError)` | the bytes as hex, for logs and tests |
| `from_bson_hex(Str hex) -> Result(T, SerialError)` | from hex |
| `bson_to_hex(List(Int) bs) -> Str` | any byte string as hex |
| `bson_encoder()` / `bson_decoder(bs)` / `bson_bytes(e)` | the raw states |

## What a BSON value is

A **document** is an int32 length, its elements, and a zero byte; the length
counts all three. An **element** is a type byte, the element's name as a
zero-terminated string, and the value. A **sequence** is a document whose
elements are named `"0"`, `"1"`, and so on. Every integer is
little-endian.

So a value's type byte belongs to its *element*, not to the value, and the
name comes between the two:

```
13000000                    a document of 19 bytes
  10 78 00 01000000         int32 element "x" holding 1
  10 79 00 02000000         int32 element "y" holding 2
  00                       the document's zero byte
```

## How the data model maps onto BSON

| Resid | BSON |
|---|---|
| a record | a document, the field names as element names |
| `List(T)`, `Set(T)`, `List(T, N)` | an array: a document whose elements are named by their index (a set in sorted order) |
| `Map(K, V)` | a document, so `K` has to be a string |
| `Str`, `Str(N)` | a string: int32 length counting the zero byte, UTF-8, zero byte |
| `ByteBuf`, `Bytes(N)` | binary, subtype 0; subtypes 2 and 4 read as bytes too |
| `Bool` | a boolean, 0 or 1 |
| `Unit`, `Option(T)` `None` | null |
| `Option(T)` `Some(v)` | `v` |
| `Int` | int32 while it fits, else int64 |
| `UInt(64)` | int32 or int64; a value above 2^63 - 1 has no BSON integer, so it is refused |
| `Int(128)`, `UInt(128)` | int32/int64 while they fit, else decimal128 (type 0x13): sixteen little-endian bytes with the sign in the top nibble of the last, so `\|v\|` must be at most 2^124 - 1 |
| `Float`, `Float(32)` | a double: BSON has one float width, so a `Float(32)` widens |
| a unit variant | its name as a string |
| a variant with a payload | a one-entry document `{name: payload}` |
| an enum with an internal tag | a document with the tag field in it, which is what `resid-derive`'s `tag = "kind"` writes |
| `Dec(N)` | its decimal text as a string |

`NaN` and the infinities are written, since a double holds both.

## The top level

The specification makes a document the top level of a stream, and a document
is what this package writes for a record, a map or a sequence — a document
whose first element's name is `"0"` is read back as a sequence. To let *any*
type be a message, a value that is not a container is written bare, with its
type byte in front of it: `to_bson_hex(1)` is `1001000000`, an int32 element's
type byte and payload with no name and no document around them. Both forms
read back, and a stream from another driver — always a document — reads as
is.

`read_peek`, which the `Value` tree uses, has to tell the two apart. It
prefers the document when the bytes ahead are a document that fills the
message: a length that reaches the end of the input, a zero byte where the
length says, and, for a document with elements, a first element of a type
this format knows. A bare int32, string or binary has a length that does not
reach the end of the input, so it is read as what it is. The one shape this
cannot tell is a hand-built bare int32 followed by exactly as many bytes as
a document of that length would need — write a document instead.

## Reading an element

`read_field`, `read_seq_next` and `read_map_next` read an element's type byte
and name and leave the type behind, so the verb that reads the value does not
read a second one. A map's key is the element's name, so `read_map_next`
leaves the state at the name and the key's `read_str` reads it as a
zero-terminated string; the type it stashed belongs to the value. An array's
count is not in the document, so `read_seq_begin` counts the elements by
walking them before the first one is read.

## Writing

A length prefix cannot be written before the bytes it counts, so the encoder
does not write bytes as it goes. Each open document collects its elements as
(name, type, bytes) triples, and when it closes it measures them, prefixes
the length, and appends the finished document to the element that was waiting
for it. A type byte is known only by the verb that writes the value, so each
element records it and the two are emitted together. A map key arrives as a
value, is written into the element, and `write_map_value` turns it into the
element's name.

## Tests

```sh
tests/run.sh             # RESIDC=/path/to/residc to pick the compiler
tests/run.sh --update    # rewrite the golden .out files
```

Five programs: the encodings the specification tabulates (`vectors`), the
whole model round-tripping (`roundtrip`), what bad bytes report (`errors`),
the `Value` tree (`value`), and instances generated by `resid-derive`
(`derive`). `run.sh` builds `resid-derive` from the sibling checkout and
regenerates `tests/model_serial.resid` before compiling.

## Requirements

A Resid compiler with the changes made alongside resid-serial (spec v3.8).
The framework lives in the sibling `../resid-serial` checkout; `resid.toml`
declares it as a dependency for the manifest tool, and `src/*.resid` import
it by path so an ordinary `residc` build works with no manifest at all.
